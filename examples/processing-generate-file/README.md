# Processing: generate the exact payment file

This Node example drives the standard Processing path with the public SDK: configure an export
profile, draft one credit transfer, validate and finalize it, and generate the exact
`pain.001.001.09` bytes for that finalized revision. It verifies the bytes against the integrity
metadata the server returns and prints only their length, digest and media type.

The example creates and finalizes records in Processing. It does not approve, release or upload a
payment, and it does not save the generated XML locally. Approval of the actual bank
submission happens on the File Exchange API, whose upload requires the agreed PGP signatures. Hand
the generated bytes to that step; never write them to disk in an example.

One authenticated identity is enough. Generation needs a finalized order and an active profile; a
draft revision is refused with a stale-version precondition failure.

## Before running

Use Node.js 24 or newer and a production account whose Processing entitlement, tenant database,
permissions and API usage-plan access have been provisioned by ISECure. WS registration alone
is insufficient. Processing has no active test deployment; use only an explicitly approved
synthetic tenant for a trial in production. See the [Processing guide](../../docs/processing.md).

Run the commands from the SDK repository after installing dependencies. The values below are
placeholders: load credentials securely, use the account details supplied during onboarding,
and choose a valid requested execution date. Do not paste real passwords into shell history.

export ISECURE_API_KEY='...'

The Nordea profile needs numeric agreement and customer identifiers; free-text identifiers are
refused at generation. Admin logins ask for an SMS or TOTP code; the shared prompt adapter reads it
from `ISECURE_MFA_CODE` or the terminal.

```sh
yarn example:processing-generate-file
```

The unit tests cover the pure helpers only: the end-to-end identifier, the generation query and the
integrity check. Running the example against a deployment is a separate, credentialed step.
